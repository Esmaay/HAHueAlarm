🌅 HAHueAlarm · design brief & reference teardown

Wake the room,
not just the sleeper.

A bedside alarm for iOS/Android built in Expo. At alarm time it does two things at once: it ramps your Philips Hue lights from dark to daylight through Home Assistant, and it plays the alarm sound. A sunrise you can’t sleep through.

Dark-first UI Sunrise light ramp Home Assistant REST 15 apps studied on Mobbin
01The concept

One alarm, two outputs — light and sound, fired together.

Standard alarms only own the speaker. HAHueAlarm also owns the room. When an alarm fires the app calls a Home Assistant service to run a gradual Hue transition while the local sound plays — and both stop when you dismiss.

🌙
T‑minus

Ramp begins early

Optional pre-alarm: Hue fades up from 1%→100% over 5–30 min so you surface from light sleep before the sound.

🔔
Alarm time

Light + sound fire

App plays the tone and sends the Hue scene/brightness to Home Assistant over its REST API.

🧠
Wake gate

Prove you’re up

Optional dismiss mission (math / shake) so you can’t swipe off the alarm half-asleep.

☀️
Dismiss

Room stays lit

Sound stops; lights hold at full daylight (or hand off to a “morning” scene) so you actually get out of bed.

02Design language

Nocturnal by default, warm at the moment of waking.

The interface lives on a bedside table in a dark room — so the ground is a deep indigo-black that won’t blind you at 6 AM. The single accent is a warm Hue “daylight” amber that only turns up where waking happens: the sunrise ramp, the active toggle, the fire moment.

04Distilled best practices

The non-negotiables the top apps share.

⏰

Reliability is the product

An alarm that misses once is uninstalled. It must fire when the app is killed, the phone is locked, and offline — via OS scheduled/full-screen notifications, never a JS timer.

🌅

Gradual > jarring

Every sleep leader (Hatch, Apple, Rise) ramps light and volume up. Sudden max-volume waking is last-gen. Our Hue ramp is this principle made physical.

🏠

Degrade gracefully

If Home Assistant is unreachable, the sound alarm still fires — the light is an enhancement, never a single point of failure. Show a quiet “couldn’t reach Hue” note after.

👆

Half-asleep ergonomics

Big targets, forgiving snooze, deliberate stop (hold / solve). Assume blurry eyes and clumsy thumbs in the dark.

🌚

True dark, low glare

Deep desaturated ground, dimmed disabled states, no pure-white flashes. The screen shares a nightstand with a sleeping person.

🔌

Setup that isn’t scary

Home Assistant URL + long-lived token, then a friendly entity picker that lists the user’s real Hue lights/scenes. Test-connection button with a clear success state.

06Technical plan

Expo stack & the Home Assistant bridge.

FrameworkExpo (SDK 53+)React Native, TypeScript, Expo Router
AlarmsNotificationsexpo-notifications, full-screen / scheduled triggers
Audioexpo-audioLooping tone, volume ramp, silent-switch aware
StorageLocal-firstAsyncStorage / expo-sqlite for alarms
Smart homeHA REST APIPOST /api/services/light/turn_on + Bearer token
Sensorsexpo-sensorsAccelerometer for the shake mission

The Hue bridge, concretely. The app talks to Home Assistant’s REST API with a long-lived access token. A sunrise is a sequence of light.turn_on calls (or one call with a long transition) targeting the chosen entities, stepping brightness_pct and color_temp_kelvin from warm-dim to bright-cool. Post-dismiss can call scene.turn_on. All network calls are wrapped so a failure never blocks the sound alarm.

Phase 1 · Foundation

Scaffold + dark design system

Expo Router project, theme tokens from section 02, navigation, the alarm list & create/edit screens with local persistence. No integrations yet — a working, beautiful alarm shell.

Phase 2 · It actually rings

Reliable alarms + ringing screen

Scheduled notifications, looping audio with volume ramp, full-screen dismiss UI, snooze, hold-to-stop. This is the make-or-break reliability work.

Phase 3 · The Hue moment

Home Assistant integration + sunrise

HA setup screen, entity picker, the sunrise ramp engine, and firing light + sound together. Graceful degradation baked in.

Phase 4 · Delight

Wake missions & polish

Shake + math dismiss gates, onboarding, sound library, settings, micro-interactions and the live-warming ringing background.
